# WARP для Windows

Клиент создаёт отдельную регистрацию Cloudflare WARP, ищет AWG endpoint с
минимальной потерей пакетов и задержкой и устанавливает системную службу
`AmneziaWGTunnel$warp`. По умолчанию это full-tunnel: маршруты `0.0.0.0/0` и
`::/0`, а также указанные DNS-серверы направляются через WARP.

Сетевой драйвер и служба не реализуются проектом заново. Клиент устанавливает
[официальный AmneziaWG for Windows](https://github.com/amnezia-vpn/amneziawg-windows-client),
проверяя SHA-256 и Authenticode-подпись MSI. Компонент регистрации и поиска
endpoint встроен в EXE клиента в сжатом виде. При установке или новом поиске
клиент извлекает его в `%ProgramData%\WARP\warp-helper.exe` и проверяет SHA-256
перед запуском. Для обычного подключения этот компонент не запускается.
Ключи хранятся в
`%ProgramData%\WARP` с доступом только для `SYSTEM` и администраторов.

## Установка

Скачайте из [последнего релиза](https://github.com/BAzeRlok/CFWARP-OPENWRT/releases/latest):

- `warp-windows.exe` — обычная Windows x64;
- `warp-windows-arm64.exe` — Windows on ARM.

Запустите EXE двойным щелчком. Клиент сам запросит права администратора и
откроет графическое окно. Нажмите **Установить**, подтвердите условия
Cloudflare и дождитесь завершения операции в журнале. Пользователю нужен только
один скачанный EXE; отдельно загружается и проверяется только официальный MSI
AmneziaWG, если приложение ещё не установлено. Отдельный helper скачивать не
нужно.

Ответ в окне подтверждает, что пользователь прочитал
[условия Cloudflare](https://www.cloudflare.com/application/terms/) и
[политику конфиденциальности](https://www.cloudflare.com/privacypolicy/).

По умолчанию исключаются российские входные узлы Cloudflare. В окне можно
изменить число проверяемых кандидатов, требуемые страны и коды узлов, а также
списки исключений. После изменения нажмите **Лучший endpoint**.

Код входного узла не гарантирует страну публичного WARP-выхода: Cloudflare
использует anycast.

Если API регистрации недоступен напрямую, клиент проверяет доступ к нему через
временные AWG-туннели. Проверяется HTTPS, а не только рукопожатие; при сетевой
ошибке выбирается другая точка. Для одного варианта маскировки проверяются до
четырёх точек, общий этап регистрации ограничен 150 секундами. Маскировка
подбирается автоматически, имя API разрешается внутри временного туннеля.
Отказы API и ошибки проверки сертификата выводятся без повторной регистрации.
Если рабочий путь не найден, в журнале будут адреса проверенных точек и ошибка.

## Управление

В графическом окне доступны:

- **Установить** — регистрация, поиск endpoint и создание full-tunnel;
- **Лучший endpoint** — новый поиск с параметрами из формы;
- **Подключить**, **Отключить** и **Переподключить**;
- **Состояние** — проверка системной службы;
- **Сторонний DNS** — включение своего сервера с выбором UDP, DoT или DoH;
- **Применить DNS** — сохранение DNS без повторного поиска endpoint;
- **Удалить** — удаление профиля и локальных ключей;
- журнал выполнения и прямые ссылки на документы Cloudflare.

`Uninstall` удаляет службу WARP, конфигурацию и локальные ключи, но оставляет
официальное приложение AmneziaWG установленным.

## Сторонний DNS

По умолчанию переключатель выключен. В форме заранее выбраны **DoH** и
`dns.zapret.moe/dns-query`. Для включения отметьте **Сторонний DNS**, проверьте
адрес и нажмите **Применить DNS**. Если WARP уже подключён, туннель кратко
перезапустится; отключённый туннель останется отключённым. До первой установки
кнопка сохраняет предпочтения для будущего подключения.

- **UDP**: IP сервера, например `8.8.8.8` или `2001:4860:4860::8888`; порт 53.
- **DoT**: имя или IP сервера, например `dns.google`; порт по умолчанию 853,
  можно указать `dns.google:853`.
- **DoH**: HTTPS-адрес, например `https://dns.zapret.moe/dns-query`.
  Префикс `https://` можно не вводить.

UDP использует штатную DNS-настройку интерфейса. Для DoT/DoH клиент устанавливает
службу `WarpExternalDNS` из копии того же EXE: она принимает запросы только на
`127.0.0.1:53`, проверяет TLS-сертификат и передаёт запросы через WARP.
Закрытие окна не останавливает DNS. Кнопки подключения, отключения и удаления
управляют обеими службами. Настройки и копия EXE находятся в
`%ProgramData%\WARP`; отдельный DNS-компонент скачивать не нужно.

Имя DoT/DoH-сервера разрешается текущим DNS при применении настроек, а его IP
сохраняются для запуска после перезагрузки без зависимости от системного DNS.
Если сервер сменил IP, повторно примените настройки при работающем DNS.
При ошибке проверки DoT/DoH после применения клиент восстанавливает прежний DNS.
Если сторонний DNS выключен, используются исходные `8.8.8.8` и `8.8.4.4`.
Настройка относится к системному DNS; приложения с собственным DoH могут
использовать свой сервер.

## Проверка исходников

```sh
cd windows
go test -race ./...
pwsh -NoProfile -File warp_test.ps1
```

Тесты проверяют DNS-протоколы, TLS, завершение службы и восстановление
конфигурации с имитацией Windows-служб. Проверка GUI и настоящего SCM требует
Windows. Для сборки из корня проекта нужны Go 1.26.3+, `curl`, `patch`,
`sha256sum`, `gzip` и `file`:

```sh
sh tools/build-windows-helper.sh
sh tools/build-windows-client.sh
```

Первый скрипт проверяет архив исходников по SHA-256 из рецепта OpenWrt,
применяет общие патчи и собирает внутренние компоненты обеих архитектур.
Для сборки без повторной загрузки можно передать `WARP_SCOUT_ARCHIVE=/path/to/warpscout-0.16.0.tar.gz`.
Второй скрипт проверяет архитектуры,
создаёт воспроизводимые gzip-ресурсы и встраивает нужный компонент в каждый EXE.
Gzip-ресурсы генерируются при сборке и не хранятся в Git.
